# Готовые балансы в Supabase

## Включение (один раз)

1. Открой свой проект на https://supabase.com/dashboard.
2. Перейди в **SQL Editor → New query**.
3. Скопируй **весь** файл `migrations/20261031_saved_balances.sql` и нажми **Run**.
4. В результате появятся текущие баллы и деньги каждого ребёнка.
5. Обнови приложение из GitHub. Если оно уже обновлено, перезагрузи страницу
   через несколько секунд: сообщение о необходимости миграции исчезнет.

Скрипт сохраняет всю историю и вычисляет начальные суммы по всем операциям.
На время переноса запись кратковременно блокируется; после завершения
ожидающие начисления продолжат выполняться. Скрипт можно запустить повторно:
он пересчитает готовые суммы по истории без двойного начисления.

## Как это работает

- `child_balances` содержит готовые баллы и деньги по имени ребёнка.
- Триггеры на `points_log` и `money_log` изменяют итог в той же транзакции,
  что и добавление, исправление или удаление операции. При ошибке отменяются
  и операция, и изменение баланса. Параллельные начисления складываются в базе.
- Детская страница запрашивает балансы, а админка дополнительно получает
  последние 20 записей каждого журнала. Индексы помогают получать эти записи
  без сортировки всей истории при каждом запросе.
- Открытый журнал сохраняет набор строк на время редактирования, чтобы новые
  записи с другого устройства не сместили редактируемые операции.
  Кнопка **Обновить журнал** получает свежие записи и сбрасывает несохранённые правки.
- Полная история остаётся в Supabase. Её нельзя удалять ради очистки экрана:
  удаление операции теперь автоматически отменяет её вклад в баланс.
- До установки миграции программа использует полный журнал, как прежде.
  Только отсутствие новой таблицы включает этот режим; ошибки доступа или сети
  не подменяются нулевыми суммами.

Настройки доступа существующих журналов и админской ссылки этот скрипт
не меняет. Новая таблица доступна для чтения тем же публичным страницам,
а её непосредственное изменение через API запрещено. Изменения проходят
через журналы и триггеры.

Для установки SQL требуется доступ владельца проекта. Обычный ключ
`SUPABASE_KEY` из Streamlit позволяет работать с данными, но не устанавливать
таблицы и триггеры через REST API.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Дополнительный тест `tests/test_saved_balances.sql` запускается **только в
отдельной тестовой PostgreSQL-базе**, после установки миграции. Он проверяет
начисления, исправления, удаления, перенос между детьми и откат транзакции.
Рабочие данные для тестирования менять не нужно.
